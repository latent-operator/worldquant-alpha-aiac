# Private PPA discovery campaign

This experiment extends the paused Nov 2026 GLB / TOP3000 / Delay 1 theme with account-visible new datasets. It uses the independent `aiac_eval_ppa` database. The existing production task 14 and old lab run 1 are read only. The old lab's 35 results and 45 locationless `UNKNOWN` requests remain unchanged.

`scripts/ppa_discovery_campaign.py prepare` reads production feedback, the frozen old manifest, and the live WQ data catalog. It selects the first usable dataset in this order: `sentiment26`, `news76`, `analyst10`; then sentiment, news, analyst, fundamental, earnings by coverage and dataset ID. Only verified MATRIX fields are eligible. The Cockpit generator proposes complete discovery groups of four, and the host validates fields, semantics, operator count, single change treatments, settings and historical signatures. The private campaign and batch files are hashed and stored outside the repository.

`run` waits until at least 24 hours after the last old connection error, rechecks the unchanged old ledger, reads current account Alphas and available active simulation inventory, verifies account authentication, production activity and platform evidence, then starts a new task/run in the lab. There is no total request cap. One batch contains at most 16 cases, and every candidate is reserved in the research ledger before its single simulation POST. A missing or uncertain POST result becomes `UNKNOWN` and stops the process. A 429 consumes its position, pauses for the platform retry interval, then proceeds with the next candidate. Three consecutive 429 responses require review. A persisted quality `PASS` stops the process for Alpha and PPA review. A complete batch is followed by a newly frozen batch; an invalid or exhausted batch stops the process.

The last old error is read from the lab ledger rather than a hardcoded timestamp. A read-only account inventory without a matching Alpha cannot prove that the 45 old requests failed. The audit records that remaining uncertainty and never mutates those rows. `report` gives each batch's candidate ID, WQ Alpha ID, request status, Fitness, Margin, persisted quality status, initial platform PPA status and final PPA status. Historical 285 and old lab 35 results are descriptive baselines only.

The runtime requires `AIAC_EVAL_LAB=1`, the dedicated loopback PostgreSQL environment, WQ credentials already available to the private launcher, a clean exact Git commit, an outside-repository directory, and separately captured current platform evidence. Use the CLI's `prepare`, `run`, and `report` commands with `--help` for arguments. The development and CI checks use mocks and make no live model, WQ simulation or submission requests. The operator must use the exact CI-passing commit before starting `run`; no production release is part of this experiment.
