# AIAC 一轮债务出清实施方案

日期：2026-11-15，Asia/Shanghai。

目标：恢复可审计的软件发布与研究恢复能力，统一请求证据解释，减少关键链路的重复判定和反向依赖。研究目标仍为同一候选持久化质量 PASS 与最终 PPA_READY；工程治理完成不等于研究成功。

架构：将请求证据判定和 Alpha 质量判定提取为无网络、无数据库副作用的策略模块；运行器、账本、对账与交接调用它们。状态持久化留在明确的事务入口。发布与研究恢复分开验收，未知历史永久保留到获得真实终态。

技术栈：Python / FastAPI / SQLAlchemy / PostgreSQL / Celery / Redis，React / Vite，PowerShell 发布脚本。以现有 preflight、Ubuntu/Windows CI、OpenSpec 和 Beads 承载本轮工作。

本文是范围与验收设计。执行状态、依赖、发现和关闭证据只在 Beads 更新，不在本文维护完成勾选。总任务 aiac-r1e.9，关联 OpenSpec `aiac-research-goal` 的 Request uncertainty、Hypothesis to feedback loop、Cross-session handoff、Business outcome evidence 要求。

## 授权与本轮边界

用户已经明确批准本次 task 14 / run 28 的未完成批次隔离交接：纠正歧义 FAILED 为 UNKNOWN，保留修改前后证据，隔离旧 run、原始位置和整个冻结批次，禁止自动恢复与重复请求。该例外只用于本次可审计软件交接，不扩展为所有 UNKNOWN 都可忽略。

默认 CI 后 CD 授权继续有效：通过 writable fork 合并，取得实际发布 SHA 的 master push CI，完成备份恢复验证、回滚来源与发布记录。实现隔离例外时同步更新工作区入口、仓库政策及其模板，避免旧文案再次覆盖已获授权；政策变更必须完整 preflight。

范围限定在请求生命周期、质量判定及直接关联的运行/发布链路。不重写全仓，不升级整套框架，不新增自主编码 Agent 或常驻治理平台，不改变 PASS 阈值，不提交 Alpha。旧 F: loop 保持暂停。未决请求所需恢复代码和回滚版本不按死代码删除。

采用五个顺序交付包，原则上一包一 PR。意外故障修复独立记录，不能把未完成问题并入“顺手重构”。同时只推进一个生产变更；诊断可以只读开展。

## 交付包 1：历史纠正、隔离交接与恢复发布

复用 aiac-r1e.8（实现）和 aiac-r1e.7（CD），不创建重复任务。

涉及：`backend/services/ppa_isolation.py`、`scripts/ppa_isolation.py`、`scripts/deploy-local.ps1`、`backend/services/task_service.py`、`backend/services/research_audit.py`、`backend/tests/unit/test_ppa_isolation.py` 及发布相关测试。

先写并运行反例：活动任务、过期或被篡改的清单、错误 task/run、已具备明确拒绝证据的 FAILED、重复隔离、旧 run 恢复、隔离签名重发，均不得被错误放行。随后实现最小路径：

1. 只读 prepare 生成仓库外私有清单，绑定授权范围、实际目标 SHA、原始候选快照和批次摘要。
2. 部署进入维护且 worker 空闲，先验证数据库备份可恢复，再原子 apply。修正仅针对证据不足的历史记录，并保存原状态、原快照、原因和时间。
3. 旧 run 使用明确的隔离交接状态/原因，游标仍为原值、未知请求仍未知。五条未发送候选不补发，也不伪造失败；其冻结签名进入隔离排除集。
4. task 14 保持研究 hold；阻止 start/resume、后台恢复和跨 run 重复请求。独立实验的 prepare/run 也必须读取隔离排除集；跨库去重不能依赖单库 SQL。
5. 发布脚本增加显式隔离模式，与完整批次/空继任 run 模式互斥。正常完整批次门槛保持原义。
6. 失败时按现有程序回退代码，不自动恢复生产数据库；隔离后的 run 不因旧版本恢复而重新启用。

验收：备份恢复校验、无丢失结果、2 条 UNKNOWN 与原位置保留、游标不伪造、16 个冻结签名可追溯且禁止重发、旧 run 不会自动恢复、API/UI/worker 使用同一发布版本且只有一个 worker。CI 与部署烟雾检查不发 WQ 或模型请求。

## 交付包 2：统一请求证据和写入约束

任务：aiac-r1e.9.1，依赖交付包 1。

建议新模块：`backend/services/request_lifecycle.py`。调整 research_audit.py、theme_ppa_v2.py、ppa_handoff.py、实验执行器及报告消费方。保持旧 JSON 快照可读，不以重构为由重写历史。

先建立共用证据表并用测试跑出差异：有 Alpha、明确 POST 拒绝、原位置明确终态失败、原位置 404/405、超时、断连、5xx、429、缺失元数据、重启恢复。返回值区分请求终态、是否需对账、是否允许另发请求，不把所有消费者强制合成一个布尔值。

账本、对账、报告和发布检查复用同一证据分类；批次完整性、研究资格和隔离授权仍由各自业务规则判断。以原生产 1777/1778 的脱敏形状作为回归样本。验证 reserve 后崩溃、POST 后丢响应、重启、并发竞争不会重复发送。

引入锁定版本的 Import Linter：纯策略不得导入数据库、适配器、Agent 或运行器；发布检查不再从研究运行器导入请求分类。引入少量 Semgrep 规则及正反例：禁止允许目录外的请求状态赋值、研究代码直接绕过受审计模拟入口等。静态规则只约束已明确的结构，不声称能证明运行时幂等性。

验收：证据表所有消费者结论一致；歧义不会计入确定失败；新增不受审计写入口为零；普通交接和隔离交接仍保持不同前提。完整 preflight、两平台 CI、实际 SHA master push CI 后按现有授权发布。

重新核实账户资格、主题有效期、实际限流证据、本地活动任务和旧实验隔离条件。首个有效冻结发现组按四例串行验证，每次 reserve/POST/位置回写/结果持久化均可追溯，重叠候选只发送一次。四例是恢复验证批次，不修改用户已选择的长期无限总预算。429 进入等待且计入已占用请求；任何新 UNKNOWN 或首个质量 PASS 立即停发复核。

若原主题在 2026-11-22 00:00 UTC 截止，届时不得沿用过期资格启动回测。平台条件不足时，可以报告工程出清通过，但真实验证保持未完成，并说明具体证据缺口；不能把时间等待当成通过。

工程退出指标：

| 指标 | 本轮验收 |
| --- | --- |
| 请求口径一致性 | 共用证据表在账本、对账、报告和门槛中无矛盾 |
| 恢复正确性 | 重启/隔离/回滚演练无重复 POST，无结果丢失，无 UNKNOWN 被强制清零 |

完整本轮退出要求上述工程条件和恢复验证均完成。若真实平台阻塞，总任务保留未完成，工程子任务可单独关闭。研究根目标只有符合既有证据验收才可关闭。

## 防止本轮再次扩张

新发现先分为发布/数据安全阻塞与可后置维护项；后者进下一轮，不扩大当前 PR。某个模块连续三次修改仍未解决同一问题时，停止追加补丁，重新追踪实际部署入口和故障证据。每个 PR 只承诺对应包的行为变化，不拿工具安装、测试数量或代码净减少量替代验收。

实施顺序为：确认基线和授权 → 失败测试 → 最小实现 → 针对性回归 → 完整 preflight → PR CI → 合并后的 master push CI → 有效交接条件下 CD → 运行证据 → 更新 Beads 并备份。下一步是继续 aiac-r1e.8 已有隔离测试和实现，不重新启动一次工具选型。
