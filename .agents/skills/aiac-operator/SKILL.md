# AIAC 操作

先读 `G:\安装\claude\work\aiac\LOCAL_CONTEXT.md` 和
`G:\安装\claude\runtime\aiac-clean\current.json`。后者记录实际运行版本、端口和解释器。
操作细节见 [原生接口与故障分流](references/operations.md)；研究时再读
[需求与社区查询](references/research.md)，查结果时读 [trace 复盘](references/review.md)。

## 识别请求

- **研究/回测/继续研究**：恢复已有约定，查历史，询问缺失要求，查社区，创建原生任务。
- **进度/结果/失败原因**：只读指定任务及结果。多个任务都可能匹配时先让用户选择；不发起新回测。
- **暂停/停止/调整**：明确任务 ID，执行相应原生控制并复查状态。暂停不表示远端在途请求已取消。
- **运行维护**：查看现有服务与队列，必要时启动现有服务。维护请求不自动变成研究请求。

## 研究交接

1. 从会话与落库结果恢复目标、地区/股票池、数据范围、质量标准、轮数与停止条件。
   只问会影响任务的缺失项，优先一次问 1～3 个问题；已明确的要求不重复确认。
   若用户委托自行选择，说明采用的假设。未答复的必要要求保持待定。
2. 检查对应数据集/字段、历史排除记录和是否已有同一研究在跑。
   Playwright 查 WQ 社区，记录来源与适用范围；遇到登录失效，等用户在浏览器登录。
   登录等待期间可分析本地 trace，不假称查过最新社区材料，也不先启动依赖它的任务。
3. 将假设、对照、既往失败和社区证据放入原生 task config/提示词。
   需求齐全后简要说明参数和限制，直接创建并启动，不再追加一次批准问题。
   用户已授权真实回测；这不包含 Alpha 提交、改账号或扩大研究范围。
4. 复用现有 Celery Worker。只在服务未运行时通过已有启动入口恢复服务，不为每个研究部署实例。
   启动请求后最多用 60 秒检查一次交接过程，不循环等待回测结果。
   返回 task/run ID、任务 URL、轮数与停止条件、已确认的排队/执行状态和未确认事项。
   API 的 RUNNING 字段不等于 Worker 已消费：优先找对应 job 接收日志或新增 trace。
   超过交接窗口仍未证实执行时，说“已入队，尚未证实执行”并结束；不另开后台监控。
5. 结束本次调度会话。计算与每轮策略分析由 AIAC 原生后台继续；Skill 不常驻，不自动唤醒聊天。
   用户下次回来询问时重新读取数据库事实，必要时查社区并复盘。只有明确要求继续研究才启动下一项研究。

## 执行边界

- 使用原生 API 或现有 `ops/research.py`。不新增执行器、轮询守护进程、任务台账或自动续批器。
- 原生默认每轮 4 个候选、批量模拟，有轮数/时长/数据集停止条件。
  不把轮数当严格请求预算，不保证无限续跑、10 路吞吐或给定表达式原样执行。
  用户要求超出原生能力时先说明差距并明确可接受方案，不用提示词冒充已实现。
- 响应超时先读任务/run/trace 再决定；不重复 POST，不重放不确定请求。
  原生适配器的重试和 fallback 仍存在，Skill 不能保证底层恰好一次执行或自动断点续跑。
- 旧 bounded 任务、UNKNOWN 和 legacy task12/task14/run28 保持冻结；保留历史排除证据。
  不直接改数据库状态、启动旧执行器或通过浏览器发送回测 POST。
- 不自动改账号、升级源码、迁移数据库、放宽质量门槛、删除历史或提交 Alpha。
  数据同步/配置修改只使用现有 API，并限于本次已授权需求；无关配置不改。
- 真实 WQ 指标是研究判断依据；执行完成、HTTP 成功、PASS 与最终 PPA_READY 分开报告。

本 Skill 由仓库维护，工作区入口只引用/同步这一份。静态说明与本地模拟验收不调用真实 WQ/LLM。
